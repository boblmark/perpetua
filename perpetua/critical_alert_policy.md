# 关键故障实时推送政策
# 用户 2026-10-15 要求：关键故障必须实时推送，不许等每日报告

## CRITICAL（立即推送到聊天）
以下情况必须立即通知用户，不许静默：
1. dispatcher 8740 DOWN（exit=2，3次重试后仍失败）
2. 发布健康 CRITICAL：距上次发布 >18h
3. OAuth token 无效（无法调 YouTube API）
4. API 配额耗尽（无法上传/翻转）
5. 数据库损坏（无法读写 ops_center.db）

## WARNING（记入每日报告，不实时推送）
1. DEGRADED 状态（H3 unknown、vids 配额 warn 等已知问题）
2. 配额使用 >70%
3. 单个视频生成失败（有重试机制）
4. 隧道/服务短暂抖动后恢复

## 判断原则
- 影响"今天能不能发出 2-3 条视频"的 → CRITICAL
- 只是"某个组件不完美但有备用"的 → WARNING
- 不确定时，偏向 CRITICAL（用户宁可被打扰，不愿错过故障）
