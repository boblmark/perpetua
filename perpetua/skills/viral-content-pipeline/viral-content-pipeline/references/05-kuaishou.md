# 05 · 快手 — 有真实的 viewCount，但池子有限

**可行性**：⚠️ 部分可得。播放量 + 点赞量真实可采；**评论/分享接口返回 null**；粉丝数登录墙。

---

## 可用入口

快手的**精选页 / 首页 / 发现页**通过 `graphql` 与 `rest` 接口返回真实数据：

- `viewCount` —— 真实公开播放量 ✅（这是快手比抖音强的地方）
- `realLikeCount` —— 真实点赞 ✅
- `collectCount` —— 收藏（仅少量行有值）

**注意**：快手页面展示的是 `841.6万` 这类中文串，接口返回的是原始整数（`8416000`）。
两者可互相印证；`1万` 这类展示串**含义确定**，可换算为 `10000`。

---

## 可用性边界（实测）

| 能力 | 状态 | 说明 |
|---|---|---|
| 播放量 | ✅ | `viewCount` 真实公开 |
| 点赞 | ✅ | `realLikeCount` |
| 收藏 | ⚠️ 部分 | 仅 ~17% 的行有值 |
| **评论** | ❌ | 接口返回 `null`（不是采集失败，是平台不返回） |
| **分享** | ❌ | 接口返回 `null` |
| **粉丝数** | ❌ | 需登录 |
| 搜索页 | ❌ | 登录墙 |
| 个人主页 | ❌ | 登录墙 |
| 翻页 `?pcursor=N` | ❌ | 触发验证码 `400002` |

### 登出态池子上限（必须标注）

本次登出态可枚举的公开池为 **294 条视频**，其中 AI/搞笑相关 24 条。
→ 这决定了行数**无法打满 60 行**，必须在 summary 中如实说明：
> 登出态可枚举的视频池存在上限（本次 294 条，其中 AI/搞笑相关 24 条），已按比例对半切分为高播放组与中位组。

---

## 视频页不是粉丝数来源（重要，勿重试）

尝试过两次用 Playwright 抓快手视频页的 document/XHR，结果：
- 捕获 11 个文档 / 96 KB
- `fansCount` / `followerCount` / `commentCount` / `userName` **全部零命中**

→ **结论：快手视频页在登出态不提供粉丝数。** 别再把时间花在这上面。

---

## 踩坑记录

| 问题 | 原因 | 解法 |
|---|---|---|
| `?pcursor=N` 返回 `400002` | 验证码风控 | 放弃翻页，用现有池子并标注上限 |
| 评论/分享为 null | 平台不返回 | 写 N/A，不要标记为"采集失败" |
| 视频页抓不到粉丝数 | 数据不在此处渲染 | 放弃（已两次验证） |
| 中文展示串与整数并存 | 前端格式化 | 用接口整数；展示串仅用于交叉校验 |
| 搜不到 AI 内容 | 池子以搞笑/整活为主 | 按平台实际调性调整选题分类 |

---

## 内容特征（本次实测）

搞笑/整活占 79%，AI 生成/数字人 17%。
30 秒–1 分钟档中位播放最高（75.4 万），3–10 分钟档最低（31.3 万）——
**快手与抖音的时长规律相反**，是很好的"平台调性决定策略"的例证。
