## ❌ Facebook Reels

**结论：登出态不可得。两块独立证据。**

### 证据 1：深挖页面结构
`watch/?v=<id>` 页面 HTML 中**确实存在** `play_count` / `reaction_count` 字段 ——
初次看到会以为有戏。但逐条比对 `video_id` 后发现：

> **所有指标字段全部属于侧边栏"推荐视频"，目标视频自身没有任何公开指标。**

`/reel/<id>` 路径多数不可用。

### 证据 2：第三方工具的同款判定
Agent Reach 在安装时直接跳过该渠道：

> 「以下渠道需要桌面环境 + Chrome，服务器环境跳过：facebook」

其设计文档亦说明：Graph API / Groups API 权限收紧，浏览器登录态是当前唯一实用路径。

**→ 需要登录态。无登录态时不要尝试任何变通。**

## ❌ 微信视频号

**结论：无公开 Web 入口。**

`channels.weixin.qq.com` 返回 `errCode 10012`（无权限）。
视频号内容仅存在于微信生态内，**没有任何公开网页可取数**。

→ 若必须覆盖该平台，只能通过人工抽样或第三方商业数据服务。

## 常见"看似可行"的陷阱

### 陷阱 1：把登录态占位值当真数据
- 小红书主页显示 `10+ 粉丝` ← **占位符**
- 部分平台未登录时显示推荐内容而非目标内容

**判别法**：数值异常整齐（全是 `10+`、`0`、`100`）或与你已知量级严重不符时，先怀疑是占位值。

### 陷阱 2：把"接口不返回"当成"采集失败"
- 快手评论/分享接口返回 `null` → 这是**平台不提供**，应写 `N/A` 并说明，不是采集失败
- 抖音 `play_count` 恒为 0 → 平台不公开

**区别很重要**：`N/A`（平台不公开）与"采集失败"（本可拿到但没拿到）在交付中的含义完全不同。

### 陷阱 3：以为换个 User-Agent / 加个请求头就能绕过
- 小红书需要**浏览器指纹级**伪装（不是 UA 字符串）
- 搜索类接口的 `-101` 是**服务端鉴权**，任何客户端手段都无解

### 陷阱 4：短超时导致文件损坏
下载大文件（浏览器二进制、数据集）时设了短超时，进程被杀但文件残留：

```
浏览器报 Bus error / file 命令报 "missing section headers"
```

**解法**：重下 + 让解压**完整跑完**；用 `stat -c%s` 校验文件大小是否符合预期。

### 陷阱 5：静默的 `try/except`
```python
try:
    CV = json.load(...)       # HERE 未定义 → NameError
except Exception:
    CV = None                 # ← 静默吞掉，交付物少了一整节却毫无提示
```
**解法**：`except` 里必须打印错误 + 在产物中写入醒目提示，绝不静默跳过。

## 汇报失败的正确姿势

对不可得的平台，交付物中必须包含**实测证据**，而不是一句"没采到"。

✅ 好的写法：
> Facebook：`watch?v=<id>` 页面内确实存在 `play_count`/`reaction_count` 字段，
> 但逐条比对 video_id 后确认**全部属于侧边栏推荐视频**，目标视频自身无任何公开指标。
> 另经 Agent Reach 独立判定同款结论（需桌面+Chrome 登录态）。

❌ 差的写法：
> Facebook 采不到。

**「能拿多少算多少 + 诚实标注缺口」远优于「为凑数而造假」。**
