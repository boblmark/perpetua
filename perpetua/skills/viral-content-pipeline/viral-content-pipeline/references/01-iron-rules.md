# 01 · 铁律与数据契约

## 铁律（违反即报废）

1. **只填公开可见的数字。看不到写 `N/A`。绝不估算、不编造、不"推算"。**
   - 禁止用词：约、大概、推算、预计、根据经验、按比例估算
   - 禁止行为：把"10万+"换算成 100000（应如实记录展示串 `10万+`）
   - 禁止行为：用互动数 ÷ 经验系数反推播放量

2. **不采集、不推断后台指标。** 完播率、留存率、点击率、流量来源、粉丝画像 —— 平台不公开，任何数值都是虚构。

3. **账号归属必须核对 ID / 主页链接。重名账号以 ID 为准。**

4. **平台不公开的字段就写 `N/A`**（如抖音播放量、小红书播放量、快手评论数）。不要因为"缺了不好看"而填数。

## 有效性判定

| 判定 | 规则 |
|---|---|
| 有效行 | 至少 `views` 或 `likes` 之一有真实值 |
| **无效行** | `views` 与 `likes` **全为 `N/A`** → 必须剔除，不得计入交付行数 |
| 合格交付 | workbook 内空单元格数 = 0（`None` 统一转 `"N/A"`） |

## 三分类字段的规则化口径（必须声明为"规则化归类"）

`topic_category` / `hook_type` / `format_notes` **不是平台官方分类**，是本流程基于真实文本的规则化归类。
交付文档里必须声明这一点，避免被误读为权威标签。

### `hook_type`（开场钩子）建议取值
`陈述开场` / `悬念提问` / `对话/冲突开场` / `对比冲突` / `反转预期` / `沉浸式/视觉奇观` / `情境代入`

### `topic_category`（选题分类）建议取值
按平台实际内容动态定义，但需**保持平台内一致**。本次实践参考：
- AI 类：`AI生成/制作`、`AI动物拟人`、`AI搞笑/整活`、`AI音乐/舞蹈`、`AI人物拟真/反差`、`AI生成/数字人`、`AI剧情/动画`、`AI美食`
- 非 AI：`搞笑/整活`、`剧情/其他`、`反转/短剧`、`AI/科技内容`

### `format_notes` 写法
只写**可观测**的信息：时长、是否循环、字幕有无、平台 AI 标注（如 TikTok 的 `ShowAIGC`）。
**不可观测项必须写"待人工核验"**，不要臆断（如"转场很流畅"这类主观判断）。

---

## 时间与口径一致性

- **同一平台的采集必须在一个批次内完成**，跨天数据不可混（播放量在涨）。
- 记录 `collected_at`，复核时用"实时值 − 库内值"判断是否为自然增长。
- 对照组的"同期"定义为：爆款作品发布日 **±2 周**窗口内。
- 平台展示 `1.2万` / `10万+` 这类串时：
  - `1.2万` → 可换算为 `12000`（含义确定）
  - `10万+` → **如实记为 `10万+`**（这是上限表示，换算成 `100000` 就变成编造）
