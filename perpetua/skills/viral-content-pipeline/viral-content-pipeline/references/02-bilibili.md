# 02 · B站（bilibili）— 唯一能拿满全字段的平台

**可行性**：✅ 完整可得。播放/点赞/评论/转发/收藏/弹幕/投币 + 粉丝数全部可采。
**推荐优先级**：第 1 个做。字段最全、最稳定，可作为其他平台的数据质量基准。

---

## 关键机制：wbi 签名

**B站视频详情接口对未签名请求返回 `-412`（风控拦截）。必须实现 wbi 签名。**

签名流程：
1. `GET https://api.bilibili.com/x/frontend/finger/spi` 拿基础值
2. `GET https://api.bilibili.com/x/web-interface/nav` → `data.wbi_img.img_url` / `sub_url`
3. 取两个 URL 的文件名（去扩展名）拼接，得到 mixin key 原始串
4. 按固定索引表重排 → `mixin_key`
5. 请求参数按 key 排序 → urlencode → 追加 `wts=<unix秒>` → `md5(query + mixin_key)` = `w_rid`

参考实现见 `scripts/collect/bili_lib.py`（已封装 `_wbi()` / `_get()`，含退避重试）。

> ⚠️ 未签名的 `/x/web-interface/view` 对本出口 IP 返回 `-412`；
> 签名后的 `/x/web-interface/wbi/view` 返回完整数据。

## 可用接口清单

| 用途 | 接口 | 签名 | 说明 |
|---|---|---|---|
| 关键词搜索 | `/x/web-interface/wbi/search/type` | ✅ 需 | 用于**发现账号与视频** |
| **独立复核用** | `/x/web-interface/search/all/v2` | ❌ 不需 | **未签名可直连**，返回真实播放/弹幕 |
| 账号信息 | `/x/web-interface/card` | ❌ | 传 `mid`，返回粉丝数 |
| 视频详情 | `/x/web-interface/wbi/view` | ✅ 需 | 全字段数据源 |
| 账号作品列表 | `/x/series/recArchivesByKeywords` | ❌ | 按关键词取该账号作品 |
| 视频标签 | 详情接口内 `tag` 字段 | — | 直接可用 |

### 复核协作技巧（重要）

**搜索接口 `search/all/v2` 不需要签名**，可作为**独立第三方来源**复核你从签名接口采集的数据。
两个不同端点相互印证，是证明"数据非编造"的最强手段。

实测做法：用爆款标题的关键词搜，在返回里按 `bvid` 匹配，比较 `play` / `danmaku`：

```
库内 8,327,176  →  实时 8,327,598  (+422)   ✅ 自然增长
库内 6,304,139  →  实时 6,304,987  (+848)   ✅
```

差值应为**小幅正值**（几百到几千）。若为负值或偏差 >5%，说明数据有问题。

## 抽样设计（B站最适合做标准范式）

每个账号 10 条 = **5 爆款 + 5 对照**：
- 爆款组：该账号近 90 天播放量最高的 5 条
- 对照组：爆款作品发布日 **±2 周**内、播放量贴近该账号**中位数**的 5 条
- 两组**不得重叠**

**组内分离自检**：爆款组最小播放量应 ≥ 对照组最大播放量（本次 8/8 账号全部通过）。

---

## 账号筛选要点

- 粉丝 10 万–500 万（中腰部）。头部千万粉数据失真，不选。
- 近 30 天有更新（用账号作品列表的发布时间判断）。
- 各账号细分风格分散，避免同质化。

## 封面 OCR

B站封面图可直接下载（`i0.hdslb.com/bfs/archive/*.jpg`）：
1. 先从详情接口取封面 URL，存到本地 `covers/<bvid>.jpg`
2. 用 OCR 提取最大文本块作为 `cover_desc`，全文存 `cover_ocr_full`
3. **未识别 ≠ 没有文字** —— 交付时须声明需人工复核

实测有效工具：`rapidocr`（本地推理，无需 API）。

## 踩坑记录

| 问题 | 原因 | 解法 |
|---|---|---|
| `-412` | 未签名 | 走 wbi 签名 |
| 搜索返回被 HTML 转义 | 标题含 `<em class="keyword">` 高亮标签 | 用正则去标签：`re.sub(r'<[^>]+>','',title)` |
| 弹幕数拿不到 | 用了 `stat` 里的错误字段 | 弹幕在 `stat.danmaku` |
| 合集播放量巨大 | 合集是"单条视频"但时长几十分钟 | 正常现象，不是异常值 |
| 同一账号两组重叠 | 只按播放量排序切分 | 必须按"发布窗口 + 中位数"双重条件切 |
