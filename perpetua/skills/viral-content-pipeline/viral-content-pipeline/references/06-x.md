# 06 · X (Twitter) — 只能按已知 ID 取数

**可行性**：⚠️ 部分可得。单条推文指标真实可采；**时间线不可枚举**，无法做账号级抽样。

---

## 核心接口：fxtwitter

```
GET https://api.fxtwitter.com/status/<tweet_id>
```

返回完整的真实指标（**需要已知推文 ID**）：

| 字段 | 含义 | 对应本流程字段 |
|---|---|---|
| `views` | 浏览量 | `views` |
| `likes` | 点赞 | `likes` |
| `replies` | 回复 | `comments` |
| `retweets` | 转发 | `shares` |
| `bookmarks` | 书签 | `collects` |

> 必须在 `format_notes` 里注明口径映射：
> `shares=retweets、collects=bookmarks、comments=replies`

---

## 根本限制：时间线不可枚举

登出态 **无法**枚举某账号的时间线或搜索结果。因此：

- **没有账号级抽样**，只能对"已知推文 ID"取数
- 样本代表性有限，**必须在交付中声明**
- 样本中容易混入非目标主题内容（本次 17 条中就含少量非 AI/搞笑 内容）

### 如何获得推文 ID

本次实践可行路径：
1. `web_search` 搜「AI viral tweet / AI video twitter」等 → 从搜索结果里提取推文链接
2. 用 fxtwitter 批量取数
3. 过滤掉缺少 `views` / 作者的无效条目

> 这是**发现受限**的抽样：得到的是"能搜到的推文"，不是"没时间线的随机样本"。

---

## 抽样分组

无账号级抽样，改用**全局播放量中位数**切分高播放组 / 中位组：

```
median(views) = 67,494  →  高播放组 8 条 / 中位组 9 条
```

**分组依据必须在 `format_notes` / `sampling_frame` 中标注**，因为这与 B站的"账号内中位数"口径不同。
