## 二、口径对照表（旧 → 新）

### daily_evolution.py（每日进化复盘）

| 维度 | 旧口径（Shorts，废弃） | 新口径（YPP 长视频） |
|---|---|---|
| teaser 判定 | 爆款 = 播放 ≥ 2x 频道均值 | GREEN = T+48h AVD(averageViewPercentage)≥75% 且 views≥30 |
| 哑火判定 | 哑火 = 播放 < 50 | RED = AVD<75% 或 views<30（任一不达标） |
| 长视频判定 | 无（按播放量一视同仁） | 观察中：T+14d 才有结论（5000 曝光 + CTR≥8% + APV≥40% + 150h + 30 订阅）；48h 窗口只报告累计观看小时与距 150h 缺口 |
| 数据缺失 | 无此概念 | 缺数：Analytics 不可用时判"缺数"，不回退到 Data API 播放量口径 |
| VvS | 无 | VvS 无 Analytics API 口径，以 48h views≥30 为分发证明 proxy（沿用 teaser_validate.py GREEN 双门） |
| 分类依据 | 无 | 时长 <90s = teaser 类，否则长视频类（Data API contentDetails 实拉） |
| 报告 | 爆款/哑火/一般三档 | GREEN / RED / 观察中 / 缺数四档 + 口径声明段 |

## 四、daily_topic_feedback.py 调整方案（未执行）

现状：赢家/输家按"昨日 24h 播放 vs 近30天中位数"判定，加权写入 topic_weights.json
→ viral_prompt.py 选题排序。相对排名机制本身不依赖绝对口径，teaser 选题继续可用。

若未来要对齐长视频口径，建议：
1. 对长视频类主题新增 `watch_minutes` 字段（Analytics estimatedMinutesWatched，
   按 video 维度拉昨日发布视频）；
2. 长视频赢家改判：小时贡献 ≥ 长视频基线（近 90 天长视频小时中位数）×1.5；
3. teaser 类保持现有播放量口径（双轨）；
4. 前提：EP 系列有 ≥3 条长视频样本后再实施，目前样本不足，改了也是噪声。

结论：暂不改，EP 系列起量后再议。
