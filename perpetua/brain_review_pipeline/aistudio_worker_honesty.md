# AI Studio：Worker 诚实性保障 MUST/NEVER 规格（2026-10-08）

共 20 条，全部可写成代码或检查脚本执行。

## MUST（必须做）

MUST-1: 每次任务上报必须附带固定 schema 的机器可验证证据载荷（task_id、起止时间戳、产物 ID/哈希、计数），缺失证据载荷的上报直接被校验器拒绝。

MUST-2: "已完成"声明必须引用至少一个本次运行中产生的、可被校验器独立拉取验证的产物（如文件哈希、DB 主键、API 响应 ID）。

MUST-3: 上报中的数量声明必须由证据产物列表计算得出（如"处理了 N 个"必须等于 len(evidence.items)），禁止由模型自由文本编造数字。

MUST-4: 失败上报必须包含完整重试轨迹（尝试次数、每次的错误码与时间戳）；"登录失败"类声明若尝试次数未达到配置的最大重试次数，校验器直接拒绝该上报。

MUST-5: 任何需要人工介入的上报之前，必须先完整执行既定重试策略（最大次数、退避间隔），重试未耗尽不得上报"需要人工"。

MUST-6: 校验器在标记任务"已验证"之前，必须对完成声明抽样回查源系统（如重查 DB/API），回查不一致即触发分级处理。

MUST-7: 证据产物必须先于上报写入（write-ahead evidence），且时间戳单调递增并落在任务窗口内，违例视为证据无效。

MUST-8: 上报中的数值字段必须以 schema 数字类型承载，不得只嵌在自由文本里，以便检查脚本做精确比对。

MUST-9: 每次运行必须输出带签名的运行记录（run_id、worker_id、schema_version），校验器验签通过才受理。

MUST-10: 违规必须分级处理：首次违规 = 警告 + 强制重跑；重复违规 = 隔离该 worker 并告警；跨 worker 出现同类模式 = 升级为策略评审。

MUST-11: 校验器误判（质疑了真实有效的上报）必须记为 checker-miss 并计入校验器精确率；校验器精确率低于阈值时只校准校验器，不得处罚 worker。

MUST-12: 被指控虚报的 worker 必须有申诉路径：带插桩重跑一次并比对结果，重跑自证清白则撤销处罚并记一次 checker-miss。

## NEVER（绝不许做）

NEVER-1: 绝不允许在零证据产物的情况下上报"已完成"。

NEVER-2: 绝不允许在重试策略未耗尽前上报"登录失败需要人工"类结论。

NEVER-3: 绝不允许自由文本中的数字与证据产物列表计数不一致；文本数字必须由列表生成。

NEVER-4: 绝不允许 worker 自行验证自己的上报；校验器必须是独立进程/服务。

NEVER-5: 绝不允许仅凭一次校验器不匹配就处罚 worker；处罚前必须经过复核（避免误伤正常 worker）。

NEVER-6: 绝不允许在任务热路径上加人工审核关卡；验证必须自动化、可异步（控制复杂度）。

NEVER-7: 绝不允许用上报文本做指标/看板；所有指标必须从证据产物派生。

NEVER-8: 绝不允许静默丢弃校验失败；每次不匹配必须带 run_id 落盘日志并路由到分级处理器。
