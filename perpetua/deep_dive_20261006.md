## 5. 针对流程/算法的优化建议

### 立即执行（P0+）

1. **发布时间强制错峰**：同一租户 4 小时内只能发 1 条，硬编码到 `youtube_upload`（Marvis 直传也要遵守，在 MCP 工具层拦截）
2. **标题主语校验**：新增规则——标题的"报应"主语必须是 Karen（或她的东西），不能是机器。`WtX4sDy2sDU` 这类"Hit It"直接打回
3. **emoji 位置校验**：标题必须以 emoji 开头（Top10 70% 规律），放末尾的打回重写
4. **元数据完整性门禁**：无标签或无描述的视频禁止上传（堵住 Marvis 直传的漏洞）

### 算法/模型

5. **v2 模型加标题结构特征**：当前 v2 的 Spearman 只有 0.27。加入以下二值特征：
   - `emoji_first`：emoji 是否在标题前 3 字符
   - `karen_punished`：报应动词的主语是否为 Karen（TOWED/SOAKED/EXPLODED/HIT 她的变体）
   - `no_jargon`：是否含 Protocol/System/Algorithm 等术语
   - 预期可将 Spearman 从 0.27 提升到 0.35+
6. **jev 彻底下线**：Pearson=-0.371 的模型留着只会误导，已从门禁移除，建议从 MCP 工具列表隐藏（保留 API 但标记 deprecated）

### 流程

7. **Marvis 直传必须过校验**：R3 的两条三无视频是绕过本机校验直接上传的。在 MCP 的 `youtube_upload` 工具层加元数据校验（标题/标签/描述非空），Marvis 调哪个路径都逃不掉
8. **哑火视频 48h 后自动换标题**：11 条中标题尚可的（如 wzps0x7Jl10），按 Top10 公式重写标题（emoji 开头+具体报应），不删重发
